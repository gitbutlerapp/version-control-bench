# jj-but Arm, k=10

Date: 2026-07-09

Batch: `tmp/pilot-runs/full-k10-20260709-103337`

Scope: 5 tasks, Codex and Claude, `jj-but+skill` only, 100 planned runs. This batch adds a fourth arm to the [2026-07-06 full matrix](full-k10-2026-07-06.md); all comparisons against `git`, `jj+skill`, and `but+skill` below read this batch against that one (same task fixtures, same graders, same configured models — `gpt-5.5` and `claude-opus-4-8` — Claude Code 2.1.198 → 2.1.205, three days apart). That makes the deltas cross-batch rather than within-batch; treat them accordingly.

`jj-but` is an agent-facing companion CLI for Jujutsu repositories built by GitButler, the benchmark maintainer — with this arm, two of the four measured tools are GitButler's. The arm mirrors `jj+skill` setup exactly (colocated `jj git init`, raw Git writes and `but` blocked) except the skill ships with the binary and is installed per run with `jj-but skill install`; plain `jj` stays available alongside `jj-but`.

## Headline

95/100 runs passed verifier checks — the first cell-level reliability break in this model generation.

Codex passed all 50 runs. Claude failed split-commit in 5 of 10 runs, and all five failures are the same defect: the three replacement commits carry the correct contents but sit on the branch in reverse order (docs → scoring → validation instead of the instructed validation → scoring → docs), graded `GRAPH_WRONG` on `commit_subjects_preserved` with every content, leftover, and topology check passing. That is a systematic ordering miss, not floundering — the five failed runs took no longer than the five that passed.

On speed, `jj-but` lands between GitButler and plain `git`, and well ahead of plain Jujutsu: both agents ran it at roughly half of `git`'s mean wall time (Codex 50.1s vs 105.9s, Claude 54.0s vs 118.0s), where `jj+skill` runs *slower* than `git` for both agents (115.9s / 167.8s). It does not catch `but+skill` (28.7s / 44.5s) overall, though Claude `jj-but` beat Claude `but+skill` on two scenarios (multi-amend 43.8s vs 64.6s, squash 41.6s vs 43.5s).

Correctness is the gate: any speed or command-count comparison below should be read within each agent and task pair.

## Failure Read

All five failures are Claude on split-commit (reps 4, 5, 6, 9, 10; reps 1-3, 7, 8 passed), all `GRAPH_WRONG`, all identical: branch subjects came out `… document lead workflow → tune lead scoring → refactor validation helpers …` where the instruction asks for validation → scoring → docs. Contents per commit, leftovers, and the commit above the split were all correct — the near-miss class, but a graded failure. Because the miss is systematic (same wrong order every time) rather than random, the likely cause is the skill's split recipe leading Claude to create the new commits top-down; the transcripts for the five runs are in the batch directory for anyone who wants to pin it down. Codex went 10/10 on the same scenario with the same skill.

## Tail Read

`jj-but` inherits a milder version of the Jujutsu right tail on Codex: two floundering-but-passing runs (455.4s split-commit, 334.4s selective-commit) pull Codex's mean (50.1s) well above its median (32.2s). That is a shorter tail than Codex `git` (max 889.6s) or Codex `jj+skill` (839.2s) in the reference batch, but it is a tail `but+skill` does not have (max 46.5s). Claude's slowest `jj-but` run was 136.9s.

## Notes

- The `git` comparison cells come from the 2026-07-06 batch, not this one, so every delta here is cross-batch: same fixtures, graders, and configured models, but a different day and a Claude Code patch release apart (2.1.198 → 2.1.205). Within-batch pairing rules from [results-presentation](../results-presentation.md) apply to everything else.
- Claude runs in this batch record ~3 failed VC commands per run; most are environment probes (a `git remote get-url origin` in a repo with no remote, a `git ls-files` settings check, and a blocked `but agentlog hook` invocation) rather than task work. Earlier batches show ~1 per Claude run. Read the Failed Task VC column, and to a lesser degree Claude's Task VC counts, with that in mind.
- Pass-rate intervals are Wilson 95% intervals over the trials in the cell; with small n they are intentionally wide.
- Trials of the same task are correlated, so cross-task claims use task-level aggregation: the paired-deltas table pairs per-task means (df = tasks - 1).
- "Tasks all-k" counts tasks where every trial passed (per-task pass^k) - the reliability gate for unattended use.
- Pre-run fixture setup, tool setup, applying task branches, skill installation, local agent instruction files, and dirty-state application are excluded from measured agent duration and command metrics.
- Claude transcript bytes and Codex transcript bytes are not directly comparable; read transcript deltas within the same agent.
