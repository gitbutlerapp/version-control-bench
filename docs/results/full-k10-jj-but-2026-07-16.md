This batch supersedes the [2026-07-09 jj-but batch](full-k10-jj-but-2026-07-09.md) as the current jj-but cell of the four-arm matrix; the other three arms are still the [2026-07-06 batch](full-k10-2026-07-06.md). `jj-but` is an agent-facing companion CLI for Jujutsu repositories built by GitButler, the benchmark maintainer — two of the four measured tools are GitButler's. Arm setup is unchanged from the 2026-07-09 batch: colocated `jj git init`, skill installed per run via `jj-but skill install`, raw Git writes and `but` blocked, plain `jj` available.

## What changed since 2026-07-09

The previous batch failed Claude's split-commit cell 5/10, every failure the identical near-miss: correct commit contents in reverse order. The transcripts showed a task-interpretation ambiguity — the agent read "replace it with A, B, C in this order" as newest-first display order — that the jj-but skill left open and the tool's unlabeled stack output reinforced. Two jj-but changes closed it (jj-but `e07fed2a` and `ba126d0d`):

- The skill's split recipe now states that a listed replacement order reads oldest→newest, says to reuse the same `--before` anchor for every insert, and names the two reversal mistakes explicitly. The same guidance was added to `commit --before`'s help.
- Reports label stack direction: `stack (newest first, top -> bottom):`.

Intermediate verification batches on the failing cell alone: 5/6 after the skill fix (`tmp/pilot-runs/jjbut-splitfix-k6-20260712`), 8/8 after the output label (`tmp/pilot-runs/jjbut-splitfix2-k8-20260712`).

## Headline

100/100 runs passed verifier checks — every cell, both agents, all ten runs. Claude split-commit, the previously failing cell, went 10/10 at 88.3s mean (from 5/10 at 101.0s).

With reliability clean, jj-but's speed profile holds from the previous batch: both agents run it at under half of plain `git`'s mean wall time (Codex 46.7s vs 105.9s, Claude 49.9s vs 118.0s), well ahead of plain Jujutsu (115.9s / 167.8s), behind `but+skill` overall (28.7s / 44.5s). Per scenario, Claude `jj-but` beats Claude `but+skill` on two of five (multi-amend 43.5s vs 64.6s, squash 32.0s vs 43.5s) and loses the other three.

Correctness is the gate: any speed or command-count comparison below should be read within each agent and task pair.

## Tail Read

One Codex reorder run floundered to 410.3s and still passed (the cell's median is 29.0s), so Codex's mean carries a tail the medians don't. Claude's slowest run in the whole batch was 139.0s. Both tails are far shorter than the `git` / `jj+skill` maxima in the reference batch (889.6s / 839.2s).

## Invalidated run

One run was invalidated and redone, disclosed here in full: the original Claude split-commit rep 4 hung with zero agent activity for two hours and was recorded `AGENT_TIMEOUT` at 7,302s despite the 900s cap. The system power log shows the machine entered sleep at 13:50:02 — two seconds after the agent's `uncommit` — and did not fully wake until 15:52:46, so the run spent essentially its entire life suspended and the timeout timer fired on wake. The interrupted artifacts are kept at `tmp/pilot-runs/full-k10-jjbut-fix-20260716/invalidated-system-sleep-036-pilot-3-split-commit-claude-r4/`; the replacement run passed in 101.3s. No other run was redone; the batch's two harness interruptions (the runner process was stopped at 43/100 and 83/100 and resumed) happened between runs and invalidated nothing.
